# Fortschrittsprotokoll: M4-008 — Lint prüft keine Workspace-Codebasis

**Datum:** 2026-10-06
**Status:** abgeschlossen

## Umfang

Karte **M4-008** („Erfolgreiches Lint-Kommando prüft keine einzige Workspace-Codebasis").

**Vorgefundener Zustand (gemessen):** `npm run lint` lief über `npm run lint --workspaces
--if-present`; **kein** Arbeitsbereich hatte ein `lint`-Skript. Das Kommando endete mit **Exit 0
ohne eine einzige Ausgabe** und hatte keine Datei angesehen — ein grüner Nachweis für nichts.

## Umsetzung

1. **Flat-Konfiguration** `eslint.config.mjs` (neu) mit risikoorientierter Regelwahl. Als **Fehler**
   geführt werden die fünf von der Karte genannten Risiken: Hooks (`rules-of-hooks`), unbehandelte
   Promises (`no-floating-promises`), sinnlose Typbehauptungen (`no-unnecessary-type-assertion`),
   ungenutzte Namen (`no-unused-vars`), erschöpfende Fallunterscheidung
   (`switch-exhaustiveness-check`) — dazu `js.configs.recommended`.
2. **`tsconfig.json` in der Wurzel** (neu). Die Pakete `packages/*` haben kein eigenes Projekt; der
   Parser meldete für **290 Dateien** „was not found by the project service" und prüfte dort keine
   Regel. Das Wurzelprojekt fasst die Produktquellen für die Prüfung zusammen (`noEmit`).
3. **`npm run lint` = `eslint .`** — kein stilles `--if-present` mehr. Der Lauf ist **Pflichtteil
   von `npm run check`**.
4. **Abgrenzung der Ausnahmen:** `work/**` (Wegwerf-Belegskripte, liegen laut Punkt M10-004
   außerhalb der Versionierung) und `packages/tools/src/catalog/generated/**` (erzeugt, wird von
   `catalog:check` geprüft) sind ausgenommen; `QM/**`, `tmp/**`, `dist/**`, `node_modules/**`.
5. **Neue Abhängigkeiten** (alle MIT): `eslint` 10.12, `@eslint/js` 10.0, `typescript-eslint` 8.71,
   `eslint-plugin-react-hooks` 7.1, `globals` 17.13. Lizenzlauf **grün**: 607 Pakete (vorher 525),
   16 vollständige Lizenztexte, 218 aufbewahrte Dokumente, **keine offenen Ausdrücke**.

### Bewusst **nicht** als Fehler geführt (mit Grund, im Bericht sichtbar)

`no-misused-promises` (60), `no-unsafe-*` (24), `unbound-method` (7), `require-await` (3),
`no-base-to-string` (1), `exhaustive-deps` (1) — als **Warnung**. Sie treffen in diesem Projekt
überwiegend gültige Muster an den Typgrenzen (Fremdbibliotheken ohne strenge Typen, `async`-Handler
in JSX). Als Fehler hätten sie 139 Treffer erzeugt, von denen der überwiegende Teil kein Risiko ist;
ein Freigabeschutz, den niemand beheben kann, wird abgeschaltet statt beachtet. Die Warnungen
bleiben sichtbar und sind eigene Folgearbeit.

Zwei Switches (`Commercial.tsx`, `packages/tools/src/index.ts`) wurden als „nicht erschöpfend"
gemeldet, führen aber ein **bewusstes `default`** — dafür ist
`considerDefaultExhaustiveForUnions: true` gesetzt; die Prüfung bleibt scharf für Switches **ohne**
Rückfall.

Zwei Steuerzeichen-Muster (`SaveFileControl.tsx`, `pdf/m8.ts`) sind **beabsichtigte**
Dateinamen-Bereinigung und mit eng begrenzter Ausnahme samt Grund im Code versehen.
