## 4. Beleg der Abnahme: frischer Checkout **ohne `work/`** (echt gefahren)

```
git worktree add --detach <Temp-Ordner> HEAD
→ Inhalt: keine work/-Datei; scripts/belege/ mit allen drei Skripten vorhanden
→ node_modules als Junction bereitgestellt (ein `npm install` im frischen Checkout wurde NICHT gefahren)
→ npm run build --workspace @commietools/web  →  Exit 0, apps/web/dist erzeugt
→ Vorschaudienst aus dem frischen Checkout auf Port 4199
→ node scripts/belege/rechner-kern-groesse.mjs                          → Exit 0, „BELEG ERBRACHT"
    heute_gesamt 59 Factories · 364.637 B roh · 103.057 B gzip (100,6 KiB)
→ COMMIETOOLS_PREVIEW_URL=… node scripts/belege/sprachpakete-netzbeleg.mjs → Exit 0, „BELEG ERBRACHT"
    Startseite 183.532 B gzip ohne Werkzeugtextpaket · Rechnerroute mit eigenem Werkzeug ·
    Bild-Metadaten-Route ohne fremdes Werkzeug
→ Belegdatei im frischen Checkout geschrieben: uebergabe/07-pruefung/hebel2/beleg-2026-10-07.txt
→ aufgeräumt: beide Vorschaudienste beendet (Ports 4173 und 4199 liefern 000), Worktree entfernt
```

**Grenze, ausdrücklich:** die Abhängigkeiten kamen als **Junction** aus dem Arbeitsbaum, nicht aus
einem `npm install` im frischen Checkout. Der Beleg zeigt damit, dass **keine** Datei unter `work/`
und **kein** fester Rechnerpfad gebraucht wird — er zeigt **nicht**, dass die Installation aus der
Registry reproduzierbar ist.

## 5. Negativproben — klarer Abbruch statt grünem Leerergebnis (4 von 4)

| Fall | Ergebnis |
|---|---|
| Vorschaudienst nicht erreichbar (`http://localhost:4999`) | **Exit 2** — „ABBRUCH (Voraussetzung fehlt): Vorschaudienst nicht erreichbar unter …" |
| Browserprogramm ist keine Programmdatei (`COMMIETOOLS_BROWSER` auf ein Verzeichnis) | **Exit 2** — „Browser startet nicht … ENOENT" |
| gebautes Bündel fehlt (`apps/web/dist` umbenannt) | **Exit 2** — „Gebautes Buendel (apps/web/dist/assets) … fehlt" |
| `node_modules/mathjs` fehlt (umbenannt) | **Exit 2** — „Abhaengigkeit mathjs (npm install) fehlt" |

**Erster Durchlauf war unbrauchbar und ist als solcher benannt:** beim ersten Anlauf fehlte
`apps/web/dist` (für einen anderen Fall umbenannt) — dadurch brachen **alle drei** Netzbeleg-Fälle
schon an der ersten Prüfung ab und die Meldungen der Fälle 2 und 3 wurden nie erreicht; die
„ok"-Zeilen jenes Laufs waren wertlos. Nach Zurückbenennen des Ordners sind die Fälle einzeln
gefahren und einzeln belegt. **Prüfmittel zuerst verdächtigt, nicht das Produkt.**

## 6. Produktbefund außerhalb der Karte (gemeldet, nicht mitbehoben)

**`HEAD` ist im frischen Checkout nicht baubar** (OP-064). Der Abnahmelauf förderte es zutage:

```
npm run build  →  License audit failed: licenses\registry.json is incomplete or stale
```

**Gemessen:** das committete Register von `HEAD` nennt `withNotices: 171 von 176` und
`noticeMissing: true` für `pdf_signer` — obwohl `crates/pdf-signer-engine/LICENSE` (Auflage A3,
34.906 B) **in `HEAD` liegt**; `lockfileSha256` weicht ebenfalls ab. Nach `licenses:generate` im
frischen Checkout stehen 172 mit Hinweis im Register und die Prüfung ist grün. Die Registerdateien
werden im Arbeitsbaum erzeugt und **bewusst nicht committet** — der geprüfte Stand liegt damit nicht
in `HEAD`.
**Nicht eigenmächtig geändert:** das ist eine getroffene Entscheidung des Betreibers (OP-036).
**Wirkung auf diese Karte:** der dokumentierte Weg für die Belege nennt deshalb jetzt
`npm run build --workspace @commietools/web`.
