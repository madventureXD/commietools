# Konzepte

Hier liegen Vorschläge und Ausarbeitungen, die noch nicht als verbindliche Architekturentscheidung gelten.

## Lebenszyklus

1. Konzept aus der Vorlage erstellen.
2. Problem, Ziele, Grenzen und Alternativen beschreiben.
3. Auswirkungen auf Local First, Offline First, UI, Sprachen, Lizenzen und Tests prüfen.
4. Konzept als `entwurf`, `in-pruefung`, `angenommen`, `verworfen` oder `umgesetzt` markieren.
5. Bei einer langfristigen Architekturentscheidung zusätzlich ein ADR anlegen.
6. Nach Umsetzung den tatsächlichen Stand und offene Punkte aktualisieren.

Dateinamen verwenden `YYYY-MM-DD-kurzer-titel.md`, damit Entstehung und Thema sofort erkennbar sind.
